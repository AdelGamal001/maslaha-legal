# قعدة مصلحة | Qaadet Maslaha

A small, bilingual legal site for GitHub Pages.
No build step, no dependencies, no cookies, no third-party fonts. The two landing pages talk to exactly three outside hosts: PostHog EU (`analytics.js`: visit counting, nothing loads when the browser says Do Not Track) and the game server's public `/stats` (`stats.js`: players online). The legal pages make no request at all.
Arabic pages use RTL; English pages use LTR.
The theme follows the device’s color preference.

## Files

- `index.html` (Arabic, default) / `en.html` (English): the landing page. Both are generated from one template by `node scripts/gen-pages.mjs` (dev-only, no dependencies), so edit `scripts/gen-pages.mjs`, not the HTML. `ar.html` and `index-en.html` are redirect stubs.
- `home.css` / `home.js`: landing styles and the small vanilla script (reveals, rolling digits, ink line). No libraries, no requests.
- `analytics.js`: privacy-light visit counting with PostHog EU (`persistence: 'memory'`, no recording, no profiles, no IP, Do Not Track respected) and the `site_cta` event on the game's Instagram links (`data-cta` = nav, hero, custom, play, footer). Loaded after the page has loaded.
- `stats.js` + `stats.json`: the «أرقام حقيقية» box. `stats.json` (`{ visitors30d, igFollowers, updatedAt }`) is written by `.github/workflows/stats.yml` (every 6 hours, or run it by hand under Actions) through `scripts/fetch-stats.mjs`; the live tile asks the game server's `/stats` once a minute. Needs three repository secrets (Settings > Secrets and variables > Actions): `POSTHOG_PERSONAL_API_KEY` (a PostHog personal API key with the "Query Read" scope), `IG_TOKEN` (a long-lived Instagram User token of the game's professional account) and `SECRETS_PAT` (a fine-grained token that may write secrets of this repository only: it lets the job store the refreshed Instagram token, because `IG_TOKEN` dies 60 days after its last refresh). Without them the tiles keep their old value or show «قريب», plus a warning line in the job. Step by step: «Changes» below.
- `img/`, `fonts/`, `favicon.ico`: game art (from the game repo), self-hosted fonts, tab icon.
- `scripts/check-site5.mjs`: dev-only check (overflow, external requests, console errors, reduced motion, links, facts, the analytics config, the real-numbers box in three data states, the numbers pipeline, the workflow lint, the token rotation, the legal text pins at one pinned game commit). Needs puppeteer-core (found in the game repo's node_modules) and Chrome; `--static` skips the browser. PostHog and the game server are never reached: their requests are answered by test doubles.
- `privacy.html` / `privacy-en.html` (anchor `#delete` = data deletion) and `terms.html` / `terms-en.html`: the privacy policy and the terms. All four are generated by `node scripts/gen-legal.mjs`: the Arabic text is copied word for word from the game repo's `docs/release/legal-site.md` **at one pinned commit** (`GAME_SHA` in `scripts/gen-legal.mjs`, read with `git show`, never from a working tree; the footer of each page says «نسخة النص: <sha>»), the English text lives in `scripts/legal-en.mjs`, and the privacy pages add the site-only sections (`SITE_SECTIONS` in `legal-en.mjs`: this website, the nightly backup, the owner's live-rooms view, the Instagram message of a supporter). To publish a newer game text: `node scripts/gen-legal.mjs --pin <sha>` (needs `SITE5_GAME_TREE` to be a clone or worktree of the game repo that contains the commit), update the English text if the Arabic changed, set `UPDATED` to the day, commit the four pages. `check-site5` fails when a page differs from what the generator produces.
- `support.html` / `support-en.html`: support contacts.
- `account-deletion.html` / `account-deletion-en.html`: deletion instructions (hand-written; they quote the real button and sheet text of the game).
- `scripts/shots-site2.mjs`: dev-only, full-page JPEG screenshots of the review pages at 390 and 1280 px into `review/site-2/`.
- `styles.css`: the single shared stylesheet.
- `.nojekyll`: disables Jekyll processing.
- `CONTENT-SOURCES.md`: claim evidence and source discrepancies.
- `README.md`: owner instructions.

## Before publishing

The support email appears on both support and both deletion pages.
The placeholder is visible and deliberately has no mailto link.
Use the same real address across both languages.
Review the content against the version you plan to release.
Check hosting configuration separately from application code.
This review cannot establish hosting-provider logs or backup behavior.

## Publish on GitHub Pages

The local repository is initialized on `main`.
No remote repository was created, and nothing was pushed.

1. Create a new public GitHub repository named `maslaha-legal`.
2. Leave its README, license, and gitignore initialization options unchecked.
3. Open PowerShell in this folder.
4. Replace `OWNER` below with your GitHub account name.
5. Run these commands yourself:

```powershell
Set-Location -LiteralPath 'G:\Work Space\maslaha-legal'
git add .
git commit -m "Add bilingual legal site"
git remote add origin https://github.com/OWNER/maslaha-legal.git
git push -u origin main
```

6. Open the repository’s **Settings → Pages**.
7. Under **Source**, choose **Deploy from a branch**.
8. Choose **main** and **/(root)**, then **Save**.
9. Wait for deployment, then open **Visit site**.
10. Check every page and language link on your phone.

Expected address: `https://OWNER.github.io/maslaha-legal/`.
All internal links are relative, supporting this project path.
Future updates require another commit and push to `main`.

Instructions follow [GitHub’s publishing-source documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Preview locally

Open `index.html` directly in your browser.
Alternatively, run this command from this folder:

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

Then visit `http://127.0.0.1:8080/`.
Press Ctrl+C to stop the preview.

## Content maintenance

Update both languages together when game behavior changes.
Keep sentences at 12 words or fewer.
Use Western digits and plain Egyptian Arabic.
Keep `CONTENT-SOURCES.md` aligned with every data-practice change.
Do not replace the current copy with outdated source paragraphs.
